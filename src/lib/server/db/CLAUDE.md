# CLAUDE.md — src/lib/server/db

Drizzle ORM layer against Supabase Postgres. See `/CLAUDE.md` for project-wide context.

## What lives here

- `client.ts` — the runtime `db` instance. `postgres.js` driver, detects pooler URLs (`pooler.supabase.com`) and switches `prepare: false`. Marked `'server-only'` — importing this from a client component fails the build.
- `schema.ts` — Drizzle table definitions + pg enums. The 8 tables mirror `src/types/index.ts`.
- `migrate.ts` — runs all migrations under `migrations/` via `drizzle-orm/postgres-js/migrator`. Invoked by `bun db:migrate`.
- `seed.ts` — creates the household, 3 Supabase auth users (idempotent), and inserts MOCK_* data via `@supabase/supabase-js` admin client + Drizzle. Invoked by `bun db:seed`.
- `migrations/` — `0000_*` auto-generated by `drizzle-kit generate`; `0001_policies.sql` is hand-written (RLS, CHECK constraints, partial unique indexes). Both tracked in `meta/_journal.json`.

## Conventions

### Column naming
**Columns are camelCase** (`householdId`, `userId`, `createdAt`). The schema uses bare `uuid()`, `text()` etc. with no explicit name argument, and neither `drizzle.config.ts` nor the runtime `drizzle()` call sets `casing: 'snake_case'`. **If you add `casing: 'snake_case'` to one without the other, queries silently fail** because they look for differently-cased columns. Either keep both off (current state) or set both.

### Currency
`numeric({ precision: 12, scale: 2, mode: 'number' })` — `mode: 'number'` makes Drizzle return a JS `number` instead of `string`. Helper: `const amount = () => numeric({...})` at the top of `schema.ts`.

### Dates
`date({ mode: 'string' })` — keeps the existing ISO-string contract from `src/types/index.ts`. Don't switch to default mode (which returns `Date`) without rewriting every consumer.

### JSONB vs child tables
`expenses.tags`, `expenses.customFields`, `incomes.customFields`, `grocery_entries.items` are all `jsonb()` with `.$type<...>()` for type safety. The decision was: nothing queries by content inside those arrays, so JSONB is simpler than a child table. Reverse it only if a feature genuinely needs `WHERE tag = 'X'` queries.

### Foreign keys & cascade
Every domain table has `householdId` (FK → households, cascade delete) and `userId` (FK → household_members, cascade delete). The cascade chain ends at `auth.users.id` — when a Supabase auth user is deleted, their `household_members` row goes, then everything they owned.

## Migrations

### Adding a column or table
1. Edit `schema.ts`.
2. `bun db:generate` — drizzle-kit diffs the schema and writes `0NNN_<random_name>.sql` plus updates `meta/_journal.json` and `meta/_snapshot.json`.
3. Inspect the generated SQL. If it looks wrong, edit `schema.ts` and regenerate (delete the new SQL + revert journal entries first).
4. `bun db:migrate` to apply.
5. **Never** hand-edit a migration that's already been applied to a shared DB — write a new one.

### Adding RLS / CHECK constraints / partial indexes
Drizzle's schema DSL doesn't express partial unique indexes, scope-conditional CHECK constraints, or RLS policies. Use a **custom migration**:

```bash
bunx drizzle-kit generate --custom --name <descriptive_name>
```

That scaffolds an empty `.sql` file AND adds it to `meta/_journal.json` so the migrator picks it up. Edit the file in place. See `0001_policies.sql` for the canonical patterns (`SECURITY DEFINER` helper, partial unique indexes via `WHERE`, scope/userId CHECK constraints).

### RLS recursion guard
`current_household_id()` is `SECURITY DEFINER` — without it, the per-row `household_id` lookup against `household_members` would recurse through that table's own RLS policy. The explicit `SET search_path = public` is hardening that must travel with `SECURITY DEFINER` everywhere.

## Don't

- Don't import from this folder anywhere outside `src/lib/server/`. The `'server-only'` marker enforces it.
- Don't hand-write `.sql` files outside `migrations/` or without scaffolding via `--custom` — the migrator won't see them.
- Don't switch the column naming or casing config mid-stream — fix the WHOLE app at once.
- Don't add `casing: 'snake_case'` to one of the two configs (drizzle.config.ts vs runtime `drizzle()`) without the other; queries break silently.
- Don't use a regular `numeric` (without `mode: 'number'`) for currency — consumers expect `number`, not `string`.
